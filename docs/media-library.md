# Built-in background library

The desktop library contains 830 choices, all at 1280 × 720:

- 80 researched themes (60 core, 20 optional), each with two scene options in five styles: AI-generated photography, painted illustration, abstract art, sculpted 3D symbols and minimal geometric graphics. This gives 800 still images (600 core, 200 optional). The second set adds a distinct subject arrangement, viewpoint or setting for the same theme, with quiet space for lyrics. Original selections are retained.
- 10 original procedural graphics, each in daylight and night lighting: 20 still images. Rain has stronger, larger visible drops and ripples.
- The original five-song pilot: 10 still images now grouped by their actual subjects (mountain paths, wheat, eagles, sea and lakes) under the regular photo and abstract styles. There is no separate sample category. Their IDs and file paths are preserved so saved backgrounds still open; historical pilot files outside the app library are unchanged.
- Watercolour/ink is removed from the picker. Its existing asset remains hidden and resolvable so older saved services still open correctly.

`assets/media/catalog.json` is the app manifest. Files live under `themes/`, `generic/` and `legacy/`. Installed builds preserve these folders under `Media/`. No cloud storage, image-search API, website scraping or image download is needed to browse or search this library.

The totals by style are photography 165, illustration 160, abstract 165, sculpted 160, minimal 160 and generic 20. Each theme has ten regular images; five themes also retain two legacy images. Both scene options share the existing theme vectors. Style buttons use purpose-drawn vector symbols that remain readable at toolbar size.

For inventory and matching questions, read the metadata first: `catalog.json` records every selectable image, `scenes.json` records the 80 themes and embedding vectors, and `search-terms.json` holds the Chinese/English visual vocabulary. `variant-set-2.json` records the second set's scene options and exact prompts; per-image provenance records the source filename, dimensions and SHA-256. There is no need to inspect image pixels to count themes or styles.

The background gallery has a visible scrollbar and a large blue, centered total count for the current collection and style filters (including results not yet loaded). Its initial batch includes one extra row to make scrolling discoverable. Resizing recalculates columns and the batch size. Scrolling down appends the next batch; earlier images and the selected background stay in place. Filtering starts a fresh batch. Each image has a single light-gray caption strip with its title and style; the tooltip retains the full title when space is tight. Double-clicking a result opens it full-screen; the lower-right expand icon also opens it without selecting it. Escape closes the full-screen image and returns to the picker. Browsing and resizing do not run the embedding model.

## Static backgrounds and PowerPoint

The library, previews and exported presentations use static backgrounds. Animation controls, playback code, MP4 files and animated WebP previews have been removed from the app. Old saved animation flags are ignored while background selections are preserved. Cancelling the background picker preserves the current selection.

Users select one of 64 colours from an 8×8 swatch palette. Font, size, bold, colour and horizontal/vertical alignment belong to each tab. For tagged lyrics, the Auto button beside the size dropdown restores a shared size based on the longest block, including title and credits. It remains active as text is edited or new blocks are added; choosing a numeric size locks the size until Auto is clicked again. The color picker and Bold button occupy the row below. There is no shaded panel behind the lyrics. Each song's opening title slide includes copyright and CCLI text at 60% of the title size. The editor now fixes the camera guide at the lower right, 40% width and height with 2% margins and a white border. The view selector, resize handles and camera dragging are unavailable; opening a service resets its preview layouts to this default. Text uses the upper half. Long credits can reduce title and credit sizes together. The illustrated worship leader remains a preview-only camera placeholder and is never exported.

The background editor above the main preview controls framing, horizontal flip and opacity. Zero opacity hides the image over white; lower values make it lighter. Drag to pan, use the wheel or stacked +/− buttons to zoom from 100% to 400%, and use the centre reset icon to reset framing. Pan is bounded so it cannot expose empty edges. These changes save per tab and apply to previews, thumbnails and exported backgrounds. The main projection preview also supports dragging to pan and the mouse wheel to zoom; both previews stay in sync, and Escape cancels a drag. The camera inset stays fixed. The main preview remains free of editing buttons, with navigation beside its heading. A padded light-gray `[section]` label appears at the lower right inside the fixed camera footprint; thumbnail badges also show slide numbers.

The Traditional/Simplified switch sits at the top right. Escape leaves an input without altering its text. With focus outside an input, Page Up/Down cycles saved services, Left/Right cycles tabs and Up/Down cycles slides. Tab starts at the song name and follows the editor fields; Shift+Tab reverses direction. Ctrl+Tab inserts indentation in the lyrics field.

PowerPoint embeds each selected image and retains editable native text and bundled font embedding. No video relationships or animation timelines are written. No video player, FFmpeg or WebView is required.

The camera-placement illustration is a separate bundled UI asset, `assets/ui/worship-leader-guitar.png`, edited with the built-in image-generation tool from the user's cartoon-stage reference. The leader plays an acoustic guitar and sings into a stand microphone on a bright white stage, wearing a visible gold cross necklace. There is no podium or wall cross. The prompt and provenance are saved alongside it. This preview artwork is embedded in the application, is not part of the 830-image background library, and never enters exported PowerPoint slides. The earlier warm-stage artwork is retained in the source folder but is no longer bundled.

Package/schema checks are automated. Native PowerPoint playback and Mac rendering still require review on those applications/devices; neither is installed on the Windows development host.

Windows and Apple Silicon use ONNX Runtime 1.31.0. Intel Mac uses the matching managed/native 1.23.2 pair, the last release verified here with an official Intel Mac binary ([upstream release](https://github.com/microsoft/onnxruntime/releases/tag/v1.23.2)). The publish step fails if the Mac native model library is absent. Native Mac inference still needs execution on a Mac.

## Local matching, only on request

Opening **Edit Background** matches the current song title and lyrics. A blank song does not trigger inference. Results are cached in memory for up to 128 distinct normalized SHA-256 keys. Section tags and presentation-only spacing are ignored; English word boundaries remain distinct. Reopening unchanged content, changing its font or switching Chinese scripts reuses the result without inference. Changed content receives a new key. Requests are serialized so simultaneous identical searches reuse the first completed match; cancelled/failed work is not cached. The first uncached match initializes the model on a worker thread. The dialog shows an extracting-themes-and-keywords overlay immediately. Model initialization uses an indeterminate bar; chunk encoding, theme ranking and keyword preparation report a percentage of completed work units, not an elapsed-time estimate. App startup, typing, switching songs and filtering metadata do not invoke it. Lyrics are never sent to an inference service or logged.

Typing custom Chinese or English terms and pressing **Search** or Enter embeds those terms and searches all 80 predefined themes. Custom text is preserved in the field and uses a separate cache key from song matching. Google remains a separate, explicitly clicked browser link.

The highest-ranked theme supplies its label plus three curated visual terms from `assets/media/search-terms.json`. The editable field shows Chinese only, using the app's selected Traditional or Simplified script. The default Google link uses only the curated English subject; descriptive details for our own images are not mandatory search terms. Editing the field uses up to three distinct phrases, translated through the curated vocabulary where available. English custom terms are preserved. Unknown Chinese terms are retained rather than silently mistranslated or replaced with a stale theme. Link construction never runs the embedding model or a translation service.

The Google Images link opens the default browser only when clicked. It now uses a short natural-language query such as `Christian worship slide background empty tomb`, without generated OR groups or exact-phrase quotes. Large and wide image filters are requested with `udm=2`, `imgsz=l`, `imgar=w` and `tbs=isz:l,iar:w`. No result-language restriction or literal `720p` keyword is added. Google controls the results; verify the downloaded image is at least 1280 × 720. Lyrics are never sent to Google. Users import selected images through file, URL, drop or paste; no image-search API is used.

A browser comparison on 2026-10-23 covered empty tomb, kneeling prayer and beach. The old long bilingual query returned more framed artwork, cutouts and stock-photo collections; adding the English words `worship slide` generally surfaced more presentation-oriented backgrounds. Adding `720p` to the empty-tomb query brought video products and unrelated thumbnails into the first screen. This was a qualitative comparison in one signed-out browser, not a ranking benchmark or a guarantee that every result is text-free, high resolution or free to use. Google's visible Tools → Size → Large selection confirmed the `tbs=isz:l` filter. [Google search help](https://support.google.com/websearch/answer/2466433) explains that quotes require exact matches; [Advanced Image Search](https://www.google.com/advanced_image_search) provides size and aspect-ratio controls.

The model is `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`, pinned to revision `e8f8c211226b894fcb81acc59f3b34ba3efd5f42`. The quantized ONNX weights occupy 118,453,870 bytes; the SentencePiece tokenizer is approximately 5 MB. `scripts/prepare-model.ps1` downloads and SHA-256-verifies build inputs. Installers bundle them for offline runtime use; weights are excluded from ordinary Git because they exceed GitHub's per-file limit.

Matching normalizes Traditional Chinese characters to Simplified Chinese using an OpenCC-derived character table, removes section tags and repeated lines, and encodes chunks of at most 126 content tokens. This is character normalization, not full phrase-aware translation. The XLM-R token IDs and pooled vectors are tested against Hugging Face tokenizer/ONNX fixtures. Mean-pooled, normalized embeddings have 384 dimensions.

The song title contributes 15% and lyrics 85% to the document representation. Theme ranking combines document/chunk similarity, explicit visual cues and a title cue bonus. Optional rare themes need an explicit cue. A diversity penalty selects four themes, displaying their available media styles. The 80 theme vectors are computed at build time; the model does not generate new pictures or claim to understand every song perfectly. Users choose the final background.

## Reproduction and provenance

All 800 regular themed images were made through the built-in OpenAI image-generation tool. Exact prompts are in `assets/media/generation-prompts.json` (first set) and `assets/media/variant-set-2.json` (second set) and `assets/media/style-expansion.json` (minimal and sculpted completion); per-image provenance and SHA-256 are in `assets/media/provenance/`. Original tool PNGs are preserved outside the repo; selected 720p JPEGs are in the workspace. The second set was visually reviewed and checked for complete theme/style coverage, unique IDs/paths, dimensions and file hashes. Generation metadata stays in the source repository and is excluded from the app package. No commercial worship publisher's artwork or lyrics are bundled.

Local development experiments prepared the prompts, normalized selected outputs, and rendered the procedural day/night artwork. These historical experiments are not distributed with this release. The checked-in catalog, assets and tests validate the application library; no generation scripts or animation assets are required to build the app.

Scene vectors, the normalization table and parity fixtures were prepared from the pinned model and are checked in. The 80 scenes came from research on a 1,318-song corpus, whose individual annotations are not all manually verified. The research corpus remains in the local development workspace and is not distributed with the application or this source release.

The app uses up to eight ONNX worker threads, reserving two logical processors on smaller PCs. On the development PC (20 logical processors), a warmed four-chunk mix measured approximately 38 ms at 4/8 threads versus 41 ms at 18 threads. More threads did not improve this short-input workload; these timings are local measurements, not a hardware guarantee.

The selected service exposes its name and date as full-width fields in the sidebar. The visible app name is 敬拜工坊. Google Drive upload setup is documented in [google-drive-setup.md](google-drive-setup.md); users do not sign in.
